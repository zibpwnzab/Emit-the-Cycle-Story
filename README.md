# [Emit-the-Cycle-Story]

**Emit-the-Cycle-Story** — это сюжетно-ориентированная приключенческая игра, разработанная на движке Unity. Сфокусирована на глубоком погружении в историю и взаимодействии с окружающим миром.

> **Примечание для .NET бэкенд рекрутеров:** Этот проект был разработан мной, Дмитрием Прокофьевым, для демонстрации навыков проектирования сложной архитектуры на языке C#. Основной акцент в описании ниже сделан не на игровой механике, а на примененных паттернах проектирования, алгоритмах и техниках оптимизации кода.

##Технологический стек
* **Язык программирования:** C# 
* **Платформа:** Unity 2022+

## Архитектурные решения и инженерный фокус

В данном проекте я уделил особое внимание созданию расширяемой и поддерживаемой кодовой базы. Ниже приведены ключевые инженерные решения, реализованные в C#:

### 1. Реализация Стейт-машины
Для управления сложной логикой поведения персонажа я отказался от громоздких цепочек `if-else` и реализовал паттерн **State** на базе `enum PlayerState`. Это позволило:
* Инкапсулировать логику каждого состояния (`Walking`, `MovingObject`, `RotatingObject`, `Stunned`) в отдельные блоки в рамках `FixedUpdate`.
* Гарантировать корректность переходов между состояниями и упростить отладку системы.

### 2. Централизованное управление системами (паттерн Singleton)
Для координации работы глобальных систем игры (`GameController`, `PlayerController`) я применил паттерн **Singleton**. Это обеспечило:
* Единую точку доступа к центральным системам из любой части кода.
* Контроль времени жизни систем с использованием `DontDestroyOnLoad`, что критично для сохранения данных между сценами.

### 3. Управление асинхронными процессами и корутины
Реализация механик, требующих задержек по времени (активация эффектов, логика перезарядки, цепочки анимаций), была выполнена с использованием асинхронных **корутин**. Это решение позволило:
* Реализовать сложную временную логику без блокировки основного потока выполнения игры.
* Оптимизировать производительность, эффективно распределяя вычисления во времени.

### 4. Слабая связанность через событийную модель
Для взаимодействия между изолированными системами (например, завершение катсцен в `CutsceneManager` или окончание диалогов) была применена **событийная модель** (подписка на колбэки). Это обеспечило:
* Реализацию принципа слабой связанности (Loose Coupling), когда одна система не знает о внутреннем устройстве другой.
* Повышение поддерживаемости и тестируемости кодовой базы.

## 📦 Как изучить код проекта
Самые интересные с точки зрения архитектуры на C# файлы находятся в папке: `/Assets/Scripts/Character` и `/Assets/Scripts/Dialogs`. Рекомендую обратить внимание на:
* `PlayerController.cs` — пример использования стейт-машины и корутин.
* `GameController.cs` — центральная система на базе Singleton.

Некоторые классы в данном проекте (например, `PlayerController`) могут быть перегружены ответственностью из-за жестких временных ограничений при разработке. Я полностью осознаю важность принципа единственной ответственности и в коммерческой бэкенд-разработке применяю практики рефакторинга для декомпозиции God-объектов на более мелкие, специализированные сервисы.
